# MSPC算法流程与接口

## 1. 目标

当可信推理、幻觉抑制、价值对齐、后门净化等安全模块共同更新同一组共享参数时，它们的梯度可能方向相反或尺度悬殊。MSPC在一次统一更新前协调这些模块梯度，并在完整模式下验证更新结果、反馈调权和回滚失败更新。

## 2. 核心流程

1. 从同一模型参数版本分别计算各安全模块损失。
2. 采集共享参数梯度及有效参数掩码。
3. 根据有效维度上的负余弦关系构建冲突矩阵。
4. 对梯度进行单位化或保尺度处理，并按照冲突强度降序进行确定性投影。
5. 结合当前风险、上一轮安全退化和历史欠优化程度计算均衡因子 `q`。
6. 在单纯形候选权重上求解风险、冲突和历史状态三目标 Pareto 协同权重 `alpha`。
7. 融合投影后的模块梯度，并写入共享参数的 `.grad`。
8. 由调用方统一执行 `optimizer.step()`。
9. 完整模式在独立验证集上检查风险、可用性和稳定性；失败时反馈调权、降低学习率或回滚。

## 3. 核心输入

| 参数 | 类型 | 形状 | 说明 |
|---|---|---|---|
| `losses` | `Sequence[Tensor]` | 每项为标量 | 同一参数版本上的多个模块损失 |
| `shared_parameters` | `Iterable[Parameter]` | - | 需要协调的共享参数 |
| `risks` | `Tensor` | `[m]` | 归一化到 `[0, 1]` 的模块风险 |
| `active_masks` | `BoolTensor` | `[m, d]` | 可选，有效参数维度掩码 |
| `config` | `MSPCConfig` | - | 数值、Pareto、反馈与回滚配置 |

其中 `m` 为安全模块数，`d` 为展平后的共享参数维度。

## 4. 核心输出

`CoordinationResult`包含：

- `alpha`：每个模块的协同权重；
- `fused_gradient`：可写回共享参数的融合梯度；
- `q`：由风险、退化和历史欠优化构成的均衡因子；
- `projected_gradients`：冲突投影后的模块梯度；
- `normalized_gradients`：单位化梯度；
- `diagnostics`：冲突矩阵、冲突比例、梯度范数、Pareto集合大小和消融配置等诊断信息。

## 5. 核心模式与完整模式

- 核心模式适合已有训练循环的平台，仅负责梯度协调和写回。
- 完整模式适合需要安全验证事务的训练任务，使用 `FullMSPCRunner.run_step()`负责更新、验证、重试和回滚。

完整模式的评估回调必须使用独立于训练批次的验证数据，避免把训练损失下降错误解释为安全性提升。

## 6. 代码对应关系

| 环节 | 文件 |
|---|---|
| 状态无量纲化 | `mspc/state.py` |
| 梯度采集和写回 | `mspc/collector.py` |
| 冲突矩阵和投影 | `mspc/conflict.py` |
| 历史退化与均衡因子 | `mspc/history.py`、`mspc/balance.py` |
| Pareto权重求解 | `mspc/pareto.py` |
| 核心协调器 | `mspc/coordinator.py` |
| 验证反馈 | `mspc/feedback.py` |
| 事务回滚 | `mspc/transaction.py` |
| 检查点和诊断持久化 | `mspc/persistence.py` |
